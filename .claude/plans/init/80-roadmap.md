# 80 — Roadmap & PR Breakdown

Principles: every PR is incremental and digestible; titles prefixed `feat/fix/doc/chore/ci`; stacked with jj where dependent. CI = unit tests only — never compilation or packaging on the development path; the single exception is M9.0's release workflow, which fires on a `v*` tag and on nothing else (70-testing-ci.md §6.5). `chore`/config/init PRs auto-merge (`gh pr merge --auto`). Feature PR descriptions are one-liners. Perf/compilation PRs must include before/after logs or metrics. UI PRs include a recording **as an animated GIF** (GitHub renders GIFs inline in a PR body; webm/mp4 attach as unviewable files — do not produce them). See 70-testing-ci.md for the WSL/headless caveat; Playwright records webm, so convert it with ffmpeg and keep only the GIF (plus a PNG still).

| M3.6 | `feat: transform controls (stretch/zoom handles, rotate, flip H/V, duplicate)` | Handles on the selection box; rotation via corner handle with angle snap (0/45/90); flip = CSS transform written back to source; duplicate = Ctrl/⌘+D cloning the element subtree with fresh `data-sl-id`s. **Shipped in two PRs.** #27 landed the rotation handle, Flip H/V, `Ctrl/⌘+D` duplicate (fresh author `id`s and `data-sl-id`s through the whole clone, with intra-clone `href`/`url(#…)`/`for`/`aria-*` references repointed) and the rotated selection box; the stretch (edge) and zoom (corner, `Shift` = aspect) handles are M3.5's. The second PR closes what the row implied but #27 did not do, and records four decisions that differ from it. **Resize under rotation** works in the element's own axes: the pointer delta is turned into the box's frame, the axis-aligned resize runs there, and the box is re-placed so the anchored edge or corner stays fixed *on screen*; the grips' cursors turn with the box. **Snapping** is PowerPoint's model rather than #27's always-45° grid (which made a 30° tilt unreachable without a modifier): free by default, magnetic at multiples of 45° within 4°, `Shift` forces 15°, `Alt` bypasses the magnet; every commit is a whole degree read back from the source, so repeated drags cannot drift. **Composing with an author transform is loud, not lossy**: `inspectTransform` decomposes only `translate rotate scale` (single-axis aliases folded), each once, in canonical relative order; a `matrix()`, `skew()`, non-canonical order, repeated function or non-`deg` angle is *opaque* — the overlay hides the grips and the rotation handle, shows the reason in a badge, and the panel's Flip buttons carry it as a disabled tooltip. Move stays available on an element positioned with `left`/`top` (a drag there never touches the transform — `translateZ(0)`, the compositing idiom, must not make an element unmovable), and on anything whose transform decomposes, by writing a **leading** `translate()` that CSS applies last, in the parent's frame. An SVG child is not exempt from the rule as an earlier revision assumed: its `x`/`y` are geometry *inside* its own user space, so a screen-space delta written there under `rotate(30deg)` moves it ~34.6px right and ~20px down — it takes the `x`/`y` channel only when the transform leaves its axes parent-aligned **and** the element is one whose position IS `x`/`y` geometry (`SVG_XY_TAGS`), and the same leading-translate channel otherwise — a `<circle>`, `<path>` or `<g>` positions by `cx`/`cy`, `d` or its own transform, so an `x` written on one is an attribute nothing reads. That set's membership is **measured in the Chromium the app ships (Electron 43), not derived from the spec**: an outermost `<svg>` is outside it (`x`/`y` are inert on a replaced element; the translate moves it, and a nested `<svg>` too) and `<tspan>` is inside it (Chromium parses a `transform` on a text-content child and declines to apply it, but honours an `x` write). Move is refused only where the transform cannot be decomposed at all, so neither channel can be shown safe. **Known gap:** the whole M3.6 transform stack reads and writes the *style* `transform` only, so an SVG element carrying the legacy `transform="rotate(30)"` **attribute** looks untransformed to the rotation handle, the flip, the duplicate nudge and this lock alike; closing that means teaching `readTransformShape`/`setStyleProp` the attribute form and is out of M3.6's scope. That refusal is the `refused` arm of **`moveChannel` in `buildFieldOps`**, the function that writes the bytes, not a check at each caller: enforced at the overlay alone it was found missing at the next entry point three rounds running (the group anchor, then align/distribute, then a source edit landing mid-drag), and enforced at `buildDragPatch` it was still missing from the panel's X/Y inputs, which reach `buildFieldOps` without passing through the drag. One `moveChannel` now answers "which channel does an X/Y edit use, and may it be written" for the reader, the writer and the message alike, so the panel field shown is by construction the field an edit would write, and the overlay's badge cannot describe a different rule from the one applied. Round 2's opaque-translate write path is subsumed by this and deleted rather than left unreachable. The panel's X/Y and the drag share one translate writer with the handles (`inspectTransform`/`composeTransform`), so a `translateX()` folds to one `translate()` rather than gaining a second and going opaque on its first drag. This reverses §5.3's "reorder to canonical and append unknowns verbatim", which kept the bytes but moved the element. A new translate is now *prepended* (`translate() rotate()`), the parent-space position, fixing an M3.3/M3.5 move that walked along a rotated element's own axis. **Flip** mirrors within the element's own frame (`scale` innermost, DrawingML's `flipH`-inside-`rot`): the tilt is kept, and text mirrors with the box — a notice says so, since CSS cannot flip a container and keep its glyphs readable. **Duplicate** folds the 16px nudge into a px translate, prepends a parent-space translate to an opaque one, and lands a non-px-translated clone (`-50%`, `1em`) in place with a notice naming the translate rather than writing `-34px` for `-50%`. ## Milestone 9 — v0.0.1 release (gated on every other milestone reaching 100%)
**Preview cadence (user request 2026-08-01):** the user installs and hand-tests the GitHub release builds, and that is the only feedback channel into the real product — `v0.0.1-preview` was how "Design Mode is off by default" and "there is no inline text editing" surfaced after ~2,700 unit tests missed both. So **after every major batch of merged feature PRs (roughly every 3–5, or any user-visible behaviour change), publish a new pre-release** from `main`: bump the tag (`v0.0.1-preview.2`, `.3`, …), ship installer + portable zip, mark the previous preview superseded in its title, verify the bundle contains the new features' symbols before publishing (a stale build shipped once), and tell the user what changed. This is a standing convention, not a one-off PR.

When all milestones above are complete (every PR merged at review confidence 100, CI green) — **including the M8b design polish pass** — cut the first release.

**M9.0 is exempt from that gate and lands immediately.** It is release *infrastructure*, not a release step: it cannot fire until someone pushes a `v*` tag, so landing it early costs nothing and changes nothing about when the release happens. Landing it early is in fact the point — it has to exist before the first tag, or that tag gets hand-built and the whole failure mode it prevents happens one more time. Everything from M9.1 down remains gated.

## Review gate (applies to every code PR)
Every code change is reviewed by a **fresh-memory subagent on Fable 5.1** (user directive 2026-08-01: all subagents — builders, reviewers, researchers — run on Fable) loaded with the repo-local [`ship-ready-review`](../../skills/ship-ready-review/SKILL.md) skill, given only the changeset. Before the first review round the branch gets a [`deslop`](../../skills/deslop/SKILL.md) pass — AI slop removed with behaviour proven unchanged by the full gate, never touching security boundaries or rationale comments. The change is fixed and re-reviewed until the verdict reaches **confidence 100 (zero blockers, zero majors, lint/typecheck/tests independently verified green)** before merge. Work done directly by the orchestrator without a subagent is held to the same bar: exhaustive self-verification plus a deslop pass.
