# Design audit + canonical token set (M8b.1)

Audited against `main` at `12d7eaf` (M3.13, #60), the commit this branch merges. Earlier rounds
measured `6c24af3` and then `a161484`; every number and citation below was re-derived on `12d7eaf`,
and §11's citation manifest pins each cited line to the text it carries there. This is the second
half of the pre-polish research:
[ui-design-direction.md](ui-design-direction.md) (M8b.0) surveyed the design skills in this
environment, ran the review-shaped ones against the renderer, studied Helium's patch set and set the
direction. **That inventory is not repeated here — it is cited.** This document does the two things
M8b.0 left to M8b.1: an **audit with counts and `file:line` citations** a reader can check, and the
**canonical token set** that M8b.2 lands and the M8b.3 fan-out converges on.

Every number below is regenerated by one committed script:

```bash
node scripts/design-inventory.mjs             # §2 — every utility and literal, by category, with file:line
node scripts/design-inventory.mjs --contrast  # §3 — WCAG ratios for the 80 fg/bg pairs the app renders, light and dark
node scripts/design-inventory.mjs --proposed  # §5 — the same check over the canonical set (63 pairs, 0 failing; exit 1 otherwise)
node scripts/design-inventory.mjs --emit-theme # §5.3 — the canonical theme block M8b.2 pastes into theme.css
node scripts/design-inventory.mjs --check [--final] [file …]   # §10 — the gates, exit 1 on any failure
```

Line numbers are exact for `main@12d7eaf`. §2's citations come straight from the script; the `sites`
column in §3 and the citations in §4 are hand-typed against the same commit (each was re-verified in
review). They do not have to be taken on trust and they do not silently rot: §11 records a hash of
every cited source line, and `node scripts/design-inventory.mjs --verify-doc` rebuilds that manifest
from the tree and fails if any cited line no longer says what it said here. Run it before executing
any part of this audit.

### 2.3 Radius — 9 spellings, 90 uses

`rounded` ×42, `rounded-full` ×12, `rounded-lg` ×7, `rounded-md` ×6, `rounded-t` ×3, `rounded-sm` ×2.
In Tailwind v4 `rounded` and `rounded-sm` are both `0.25rem`, so `ThumbnailRail.tsx:159` (`rounded`)
and `:165` (`rounded-sm`) paint the same corner while reading as different in source; `FormatBar.tsx:102`

**6px** (6 uses, all `ExportPptxDialog` + `AuthTab` cards), **8px** (7 uses: chat bubbles, arrange bar,
both dialogs), **pill** (12 uses: context chips, HUD pills, present controls, budget bar, rotate handle).

(`outer = inner + padding`) holds nowhere. Ceiling is 8px everywhere, which matches Helium's `kMSmall`

## 3. Measured contrast

Method: WCAG 2.1 relative luminance from sRGB; Tailwind v4 palette colours converted from their
OKLCH definitions in `node_modules/tailwindcss/theme.css`; alpha layers composited in order over the
opaque ground they actually sit on. The composite grounds (all opaque results):

| Ground | Composition | Light | Dark |
| --- | --- | --- | --- |
| canvas mat | `canvas-mat/25` over `shell-bg` · `black/40` over `ink` (`SlideCanvas.tsx:104`) | `#d5d5d5` | `#131314` |
| property panel | `shell-bg/95` · `ink-alt/95` over the mat (`PropertyPanel.tsx:250`) | `#f1f1f1` | `#25252a` |
| dialog scrim | `black/40` over the app ground | `#929292` | `#131314` |
| HUD pill | `black/70` over a white slide · over `ink-alt` | `#4d4d4d` | `#0b0b0d` |
| arrange bar | `white/95` · `ink-alt/95` over the slide | `#ffffff` | `#26262b` |

Thresholds: **4.5:1** for text (nothing in the chrome reaches WCAG's 18.66px-bold "large" size),
**3:1** for UI components (WCAG 1.4.11). Disabled controls and `aria-hidden` decoration are exempt
and reported only in the script output. 80 pairs measured; the full table is `--contrast`. **25 failed
when this was written; 17 fail on this tree** — M8b.1a (#68) closed four (T1, T2, T3, U14), M8b.2's dark
`accent` value closed four more (T4, T5, U10, U15), M8b.2 **opened one that did not exist before**
(T7, below), and **M8b.1c closed that one**: 25 − 8 + 1 − 1 = 17. The only text pair still failing is
T6, at 4.34 light.

**`--contrast`'s own light column is wrong on this tree, and the count it prints (20) is not the 17 above.**
`currentPalette()` reads `theme.css` with one flat `--color-<name>: <value>` regex and takes the last
declaration of each name. That was sound while every token had exactly one value; #69 added
`@media (prefers-color-scheme: dark) { :root { … } }` with 22 overrides, so `accent`, `accent-soft`,
`danger` and `warning` now resolve to their **dark** values in both of `--contrast`'s columns. Observed:
the `# Current palette` table prints `accent` as `#ed6444` (`oklch(0.670 …)`) though `theme.css:49`
declares the light value `oklch(0.554 …)`, and pair #22 reads `3.09` light where the light value gives
`4.97`. **Nineteen** pairs move, not fifteen: #10, #11, #12, #21, #22, #23, #24, #48, #49, #50, #51, #52, #53, #54, #56, #57, #73, #74, #79. Fifteen is the count once you drop the four in which `accent` appears only as a low-alpha tint composited into the *ground* (#10, #11, #12, #57, `accent/5` and `accent/10`), which shift by at most 0.52; the other fifteen have `accent` as the measured foreground or as an opaque or alpha fill. Re-derive by diffing the light column of `--contrast` against a run with `theme.css` truncated before its `@media (prefers-color-scheme: dark)` block. Three of them — #21, #22, #23, all `accent` as text — are reported
**fail light** when they pass in both modes; that is the whole of the 20-versus-17 gap. So the *identity*
of the failures is wrong, not only the count. Until M8b.1c, #24 was a fourth: `white` on `accent` was
printed **fail both** where it truly failed dark only, and the gap was 21 versus 18. Now that #24 is
`on-fill` on `accent` it passes in both columns of both runs (5.83 printed, 5.19 true light) and only the
three `accent`-as-text rows are misreported.

The 17 above is therefore derived, not printed: the light column from a `--contrast` run against a
`theme.css` truncated at the dark block (light values in both columns, which reproduces every ratio §3.1
already records, to ±0.01), the dark column from `--contrast` as it stands (dark values in both columns),
then the WCAG floors applied per kind. Roadmap **M8b.1b** fixes the script by giving `--contrast` two
resolvers the way `--check`'s census already has; §10's unguarded list carries the defect until it does.

## 5. The canonical token set

### 5.1 Principles (decisions, each traceable to M8b.0)

1. **Extend, don't rename.** `theme.css` declares 18 colour tokens today. The 14 mode-bound ones
   (`shell-*`, `chrome-*`, `ink-*`, `canvas-mat`, and M4.5's `danger-dark`/`warning-dark` — §5.9)
   keep their names and values until they are retired; the other four are canonical role names
   already, so the role block re-values them in place: `accent` keeps its light value and gains a
   dark one, `accent-soft` is re-valued (it has no consumers), and `danger`/`warning` become
   mode-swapping. New **role** tokens are added beside the 14; components migrate surface by surface
   in M8b.3; the legacy tokens are deleted in the last M8b.3 PR behind the two survivor checks in
   §5.4 — **not** behind `theme-tokens.test.ts` as shipped, which derives the namespaces it polices
   from the tokens still declared (by design, see its header) and therefore goes blind to a deleted
   namespace: deleting the 14 legacy declarations with the renderer untouched leaves 328 `.tsx`
   references standing (332 counting `body`'s four `var()` consumers, which no utility scan sees)
   and the shipped test sees almost none of them. **Corrected in M8b.2 review round 1 — the run is
   not green.** Measured on this document's own tree (`30ca973`), the un-claused test reds at exactly
   **2** sites, `danger-dark` and `warning-dark`: M4.5 had already declared `--color-danger` and
   `--color-warning`, which are canonical role names, so deleting the 14 does not take the `danger` /
   `warning` namespaces with them and the test keeps policing their `*-dark` suffixes. With M8b.2's
   role block landed it reds at **3** — the extra one is `canvas-mat`, revived the same way by the new
   `--color-canvas`. The argument is unchanged and the clause is what earns its place: the un-claused
   test misses **352 of 354** references on base and **351 of 354** with the block landed (**352 of
   355** once M8b.1a landed on top — the reference total moves with the renderer, the 3 does not).
   **Re-measured on `774b356`** (`--check --final` and the clause's own mutation): `--final` counts **354**
   utility references — the four `body` `var()`s are gone, M8b.2 migrated them — and the clause reds at
   **355** `file:line → token` pairs over 128 lines in 18 files, the un-claused test still at **3**. This
   reaches M8b.0 §5.1's role-bound end state with no repo-wide rename and no merge-conflict
   machine.
2. **One role, one token, values swap by mode.** A role token is declared once in `@theme` with its
   light value and overridden in `@media (prefers-color-scheme: dark) { :root { … } }`. Tailwind emits
   `background-color: var(--color-surface)` (verified, §5.7), so the override reaches every utility
   and a component writes `bg-surface` with **no `dark:` variant**. Bare `:root` therefore carries the
   complete light palette and dark redefines only what changes — no colour has its only definition
   inside a media query (the existing convention, kept).
3. **One neutral family, both modes.** The shipped dark neutrals are a cool grey (`H ≈ 286`,
   `C 0.005–0.014`); the light neutrals are pure grey (`C = 0`). Helium's replacement neutral ramp is
   `oklch(0.48–0.83, 0.033, 279–282)` (computed from the hexes M8b.0 §4.1 quotes) — the same family.
   So the light neutrals take hue 286 at `C 0.002–0.006`, the dark values stay byte-identical, and
   `canvas` is the one achromatic token, so the mat never tints a slide's colours. Lightness of the
   light neutrals is kept where it was measured to work (`text` 0.222, `text-muted` 0.485, `surface`
   0.985, `line` 0.905 ≈ `chrome-line`'s 0.913).
4. **One base unit.** Tailwind's 4px `--spacing` is the base; every dimension token below is a multiple
   of it, including the 28px control (7 × 4) — Helium's `kToolbarButtonHeight` and our `h-7`. Type
   line-heights are 16 / 16 / 20 / 20 so an 11px caption in a `py-0.5` chip is 20px and a 13px label
   in a `py-1` control is 28px — the control height falls out of the type token.
5. **Ceilings, not menus.** Three radii (4 / 6 / 8) plus pill for chips and HUDs; three shadows; four
   type sizes; three weights; two easings; four durations. Tailwind's default scales for radius,
   shadow, text, weight, tracking, leading, ease and animate are **reset with `--*: initial`** so
   `rounded-xl`, `text-sm`, `font-bold`, `ease-in` and `animate-pulse` stop existing as utilities — the
   guard is the compiler, before M8b.4's test. The resets cannot remove numeric or static spellings:
   `leading-N` (spacing-based — `leading-4`, the app's most-used leading, still compiles),
   `duration-N`, `z-N`, `ease-linear`, `rounded-none`/`rounded-full`. Those are M8b.4's check (6).
6. **Semantic hues are status only.** `danger`, `warning`, `success` never touch chrome, selection or
   emphasis; each status also carries a word or icon. The editing frame gets `edit` (blue) and the
   guides `guide` (teal) so the warning amber and the future AI-pending violet
   (40-design-mode.md §"AI pending") each keep one meaning.
7. **Accent unchanged in light; lifted in dark.** `#c43e1c` = `oklch(0.554 0.176 34.8)` stays. Dark
   uses `oklch(0.67 0.176 34.8)` = `#ed6444` (M8b.0 §2.2's value, re-verified: 5.09 on `surface`,
   4.66 on `surface-raised`). Because a lifted accent is too light for white text (3.23:1), **`on-fill`
   is a role token** — white in light, near-black in dark — and the same token is the text on every
   saturated fill (`accent`, `danger`, `warning`, `success`, `edit`): 5.19–7.13 light, 5.83–10.6 dark.

compares the declared strings (`PROPOSED_LIGHT` / `PROPOSED_DARK` in the script, echoed by

- **R2** Palette colours (`red-*`, `amber-*`, `neutral-*`, `fuchsia-*`, …) do not appear in components; `white`/`black` only through `hud`, `scrim`, `on-fill`.
- **R3** Alpha on a token (`accent/10`) is not a way to invent a colour; the one permitted alpha is `hud-fg/70` (secondary HUD text, 5.17:1 measured); the HUD hover is the `hud-strong` token, never `hud/85`.

### 5.9 M4.5's semantic tokens — the collision, and who resolves it

PR #63 added four tokens to the legacy `@theme`: `--color-danger` and `--color-warning` (light-only
values) plus `--color-danger-dark` and `--color-warning-dark`, the mode-bound twins that make them
readable on `ink`. Two of those names — `danger`, `warning` — are canonical role names, so the role
block **replaces** them exactly as it replaces `accent`/`accent-soft`; their canonical values are
mode-swapping, declared once in `@theme static` and overridden in the dark `:root`. The twins have
no canonical counterpart and **retire with the other twelve** (14 retired tokens, not 12).

Two consequences the fan-out must not discover on its own:

1. `--check`'s "has the role block landed?" quorum ignores the four pre-existing role names, so two
   coincidentally-named legacy declarations cannot flip an unmigrated tree into post-M8b.2 mode
   (§10 row 24). Their *values* are still byte-checked once the block lands.
2. **`semantic-contrast.test.ts` is a fourth class-coupled test**, alongside `slide-canvas-dock`,
   `thumbnail-rail` and `status-bar-meter`. Its usage half asserts that every `text-danger` /
   `text-warning` carries a `dark:` twin — which R1 forbids once the role tokens land, since the
   value then swaps in `:root` and the twin would pin a dark value in light mode. Its values half
   reads hex out of the first `@theme` block and will not find the canonical `oklch()`. The **§7 row
   7 status-bar PR owns both halves**: it drops the two twins, replaces the usage assertion with one
   that forbids a `dark:` twin on a role token, and re-points the values half at the 63-pair census
   (`--check`), recording the mutation as §7 requires. Until that PR lands, the twins stay and R1's
   carve-out applies. **M8b.1c (#74) added a third clause to the same file** — the opaque-`bg-accent`
   /`text-white` pair scanner of §10 row 26, which is what keeps T7 closed. It is independent of the
   two halves above and must survive that rewrite. Its `text-on-fill` floor (`paired >= 10`) will fall
   **legitimately** when a surface PR moves its buttons onto `<Button>`, which spells the token once
   inside the primitive: lower the floor then, do not delete the clause.

### 5.5 Compatibility with the `.sloodge` deck theme (30-slide-format.md §4)

- **Different documents, different namespaces.** Deck tokens are `--sl-*` inside each slide's own
  iframe document; chrome tokens are `--color-*` in the renderer document. They cannot collide, and
  `wrapSlideHtml`/`frameScript` inject no chrome CSS variables into a slide.
- **Different palettes on purpose.** The chrome accent is warm (`34.8°`); the default deck accent in
  30-slide-format.md is cool (`#4c8dff` = `oklch(0.658 0.182 261)`). The Design Mode colour picker
  offers **deck** swatches (`theme-swatches.test.ts`), never chrome tokens; chrome never draws with
  `--sl-*`. The `edit` token (`262.9°`) is close in hue to that default deck accent — acceptable
  because `edit` appears only as a dashed 2px frame with a labelled chip and never as a fill the
  slide could be confused with; if a future default theme moves to blue-orange, revisit.
- **The mat is achromatic** (`canvas`, `C = 0`) so slide colours are judged against neutral grey, as
  in every image editor; that is the one place the "choose your neutrals" rule is deliberately broken.
- **Same English words, separate CSS**: the deck schema names `surface`, `border`, `ok`, `warn`,
  `danger` (`theme.json`, emitted as `--sl-color-*`); chrome names `surface`, `line`, `success`,
  `warning`, `danger` (`--color-*`). Different documents, different prefixes — no collision, and the
  fan-out must not "align" them: renaming either buys nothing and the deck schema is versioned.
- **Chart series**: `tokens.series[]` is a deck concern (M8b.0 §9 — validate with `dataviz`'s script
  in a later milestone); chrome defines no series colours.

emitted CSS then carries the full role block, the PR is reviewable and diffable, and the dark
overrides have something to override in the build that introduces them.

### 5.8 The canonical strings are Prettier's normal form — both halves of M8b.2's DoD hold at once

`--check` compares each declaration **byte for byte** against the canonical string, and `pnpm lint`
runs `prettier --check .`, which formats `theme.css`. Those two are only compatible if the canonical
values are already written the way Prettier writes them, so they are: Prettier strips trailing zeros
in a decimal (`0.600` → `0.6`, `0.020` → `0.02`, `26.0` → `26`), and every canonical value here is in
that form. Verified both directions on the landed tree: `--check` → `49/49 … RESULT: pass` **and**
`prettier --check src/renderer/src/styles/theme.css` → `All matched files use Prettier code style!`.

Before this was aligned the two gates were mutually unsatisfiable — a Prettier-clean `theme.css`
scored `38/49`, `FAIL (11)` (`theme.css has oklch(0.6 0.008 286), canonical is oklch(0.600 0.008 286)`
and ten more), so M8b.2 could satisfy its `--check` half or its `pnpm lint` half but never both.
`--emit-theme` also emits the block already indented (2 spaces inside `@theme`, 4 inside the dark
`:root`), so the paste is Prettier-clean as it lands. **M8b.2 must not re-wrap, re-space or
re-round the emitted values** — byte-equality is the gate, and `--*: initial` resets and hue values
are equally literal. If a value ever has to change, change it in `scripts/design-inventory.mjs`'s
`PROPOSED_LIGHT`/`PROPOSED_DARK` and re-emit; never hand-edit `theme.css` to match.

## 9. What the existing guard covers, and what M8b.4 adds

`tests/unit/design/theme-tokens.test.ts` (PR #47) already fails when a colour utility names a
`--color-*` token that `theme.css` does not declare, across every declared namespace, through variants
and alpha suffixes. It does **not** see: palette colours (`bg-red-500` is a valid Tailwind colour),
raw literals (`rgba(…)`, `#hex`) in class strings or `style` props, arbitrary values, palette colours,
alpha suffixes, `dark:` on role tokens, retired tokens once deleted, or — because it is
namespace-scoped by design — a typo in a role *name* (`bg-surfce` passes it; verified in review).

`scripts/design-inventory.mjs --check` covers most of that today, on every file or on the files named:
the allow-list form of check (1) — every colour-shaped utility and every `var(--color-*)` names a
declared token, a retired token, a palette colour or `transparent|current|inherit`, and palette
colours are then a column of their own — plus `dark:`, arbitrary values, alpha suffixes other than
`hud-fg/70`, retired tokens; and once the block lands, the declared values, the census, reachability
and the resets. What M8b.4 adds: it turns `--check` into a **suite-run test over every file**, so a
regression after a surface has migrated fails `pnpm test` rather than a command someone must remember;
and it scans what `--check` does not — raw literals (`#hex`, `rgb()`, `oklch()`) in class strings and
`style` props, and the numeric spellings the resets cannot kill (`leading-N`, `duration-N`, `z-N`,
`ease-linear`). Allow-list with a reason per entry (`-mb-px`; `max-w-[90vw]`-style viewport clamps on
dialogs; `slide://` URL strings that contain `#`). Eight mutations, each observable in the per-file row
or the raw-literal list: `text-[13px]`, `bg-red-500`, a raw `rgba()` shadow, `dark:bg-ink-alt` on a
migrated file, `bg-chrome` after retirement, `bg-surfce`, `bg-accent/10`, `leading-4`.

A citation written as a range records both of its endpoints; the lines between are the region's
contents and are deliberately not hashed, so an edit inside a cited region does not red a citation

pass: when `--verify-doc` reds, read the moved lines it prints and fix the prose that cites them
