# Code-Review Skill — Research Summary

Skill: `.claude/skills/ship-ready-review/` (SKILL.md + `references/electron-security-checklist.md`). Fetched 2026-07-31.

1. **Anthropic prompting best practices** (platform.claude.com/docs/.../claude-prompting-best-practices) — be explicit about the contract, give one strict output template rather than prose latitude, and state the success criterion directly ("actively hunted for a reason to block") instead of implying it.
2. **Anthropic Agent Skills best practices** (local `agent-skills-best-practices.md`) — third-person trigger-rich `description`, SKILL.md under 500 lines (it is 299), progressive disclosure with reference files exactly one hop deep, TOC on any reference over 100 lines, checklist-in-response pattern for multi-step workflows.
3. **Claude Code best practices** (code.claude.com/docs/en/best-practices) — "give Claude a way to verify its work" and "the trust-then-verify gap" are why Step 3 mandates running `pnpm lint`/`typecheck`/`test` and citing exit codes; also its warning that a reviewer told to find gaps will invent them, which motivated the strict minor/major/blocker split where minors never block.
4. **Google eng-practices, "What to look for in a code review"** — supplied the review standard adopted verbatim ("approve once the change definitively improves code health, even if imperfect"), the design/functionality/complexity/tests/naming/comments/consistency axes, and the "Nit:" convention for non-mandatory comments.
5. **Cursor thermo-nuclear-code-quality-review SKILL.md** — the demanding-but-not-rude tone, "do not approve merely because it works", high-conviction findings over cosmetic lists, and "propose the restructure concretely or don't raise it" (checklist item 20).
6. **Electron security recommendations** (electronjs.org/docs/latest/tutorial/security, all 20 items) — the backbone of the reference file: sandbox/contextIsolation/nodeIntegration, IPC sender validation, CSP, navigation and `setWindowOpenHandler` limits, and the `shell.openExternal` scheme rule (which flags a real gap in the current `src/main/index.ts`).
7. **Martin Fowler on code smells** — smells are surface indicators, not verdicts; encoded as the major/minor boundary test ("will this cost someone real time in three months?") so duplication/naming/dead-code findings are argued, not asserted.
8. **Repo-grounded constraints** — read from `11-tech-stack.md`, `70-testing-ci.md`, `30-slide-format.md`, `40-design-mode.md`, `.oxlintrc.json`, and `src/`: strict TS flags (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), `main → shared ← renderer` dependency direction enforced by oxlint `no-restricted-imports`, CI runs lint+test only (typecheck is the reviewer's job), the `IPC_REQUEST_CHANNELS` runtime allow-list, and the `sandbox="allow-scripts"` opaque-origin slide iframe whose bridge must check `event.source`, not `event.origin`.
9. **Confidence calibration** is defined as a minimum-of-caps ladder rather than a vibe: blocker ≤40, major ≤85, unverified checks ≤60, unreadable code ≤75, fewer than three break-hypotheses ≤90, minors-only ≤99; 100 requires zero blockers, zero majors, green lint+typecheck+test, and three recorded falsified hypotheses.
10. **Verdict shape**: one JSON block — `{confidence, verdict, blockers[], majors[], minors[], notes}` — where every finding carries `file`/`line`/`what`/`why`/`fix` and `notes` records the exact commands run and the break-hypotheses tested, so the caller can audit the review rather than trust it.
